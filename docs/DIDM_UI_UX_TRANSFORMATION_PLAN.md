# UI/UX transformation plan

Assessment: 17 November 2026, Asia/Kolkata. This report distinguishes implemented code, verified behavior and work still required. No production deployment or database migration performed.

## Design direction and implemented scope
DIDM red, warm paper, near-black text, quiet borders and real campus imagery support an editorial education experience. The homepage reuses the creative studio, giving readable positioning and meaningful program/counselling actions first-screen priority. A new student journey band connects courses and schedules. New workflows share `styles/student-experience.css`, bounded to their own classes. Existing global presentation layers, motion, original images and page templates remain.

## Component inventory
| Component | Purpose | Data / behavior |
|---|---|---|
| CreativeStudioHero | Existing animated creative visual, improved composition | Published CMS heading/media, static fallback, program CTA |
| CourseFinder | Five question guided choice | Lightweight existing catalog, explicit choice required, top three reasons, back/reset |
| CareerExplorer | Six career directions | Skills/projects clearly marked suggested, real course links |

| EnquiryForm | Admission request | Accessible labels, honest confirmed/failed status, direct human handoff |
| MotionSection | Existing reusable choreography | SSR-visible content, scoped GSAP, reduced-motion support |

## Page-by-page follow-up
Homepage: review inherited awards/testimonials/partner claims; reduce repeated long sections after conversion research. Course directory: catalog owner should approve suitability and duration. Detail pages: converge common and bespoke pages without losing curriculum or forms; add approved fees and contextual batches. Centres: reconcile Varanasi and confirm local contacts; connect shared schedule service. Outcomes/stories: publish only consented evidence with dates and source attribution. Faculty: verify current staff. Resources: approve editorial content before indexing as official guidance. Contact: test real CRM delivery with isolated credentials. Admin: extend existing module foundations, not a second panel.

## Accessibility and performance
Semantic headings/legends, associated labels, native radio/select/range inputs, explicit button states, visible focus, live result messages, skip link to focusable main. Responsive layouts checked at desktop/tablet/mobile widths. Reduced motion preserves content. No new dependency or external AI call. Full WCAG contrast, screen-reader and assistive-device certification remains outstanding.
